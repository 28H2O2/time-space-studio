# 发给 dot 的维护提示词

在 dot 可以访问并写入此 GitHub 仓库的环境中使用下面的提示词。先执行一次手动更新，确认真正产生提交、通过 CI，并由 Vercel 上线。定时触发是否可用需在 dot 中实际确认；这份文件本身不是定时任务。

---

请维护公开网站仓库 https://github.com/28H2O2/time-space-studio 。先阅读 README.md、docs/content-workflow.md 和 src/lib/types.ts，再核对当前内容与 Git 状态。

每天按 Asia/Taipei 日期，选 3 件可展示的视觉参考作品。以时间、空间、历史地理、交通、信息关系图为主，并加入当代平面设计、艺术、交互叙事和跨媒介作品；按周约六成聚焦时空内容，避免连续重复同一种图。优先一手机构和设计师来源。请实际查看图像，核验作者、年代、原始出处和使用依据，中文短评直接由你撰写，不调用 Gemini。writing.author 填 dot，不猜测底层模型。

把核验后的作品、短评、来源、许可和新一期选图写入 content/library.json，获准缓存的图片写入 public/media/。无法可靠展示的作品仅加入原站入口，不计入当天三张图。保留历史文字的真实来源。稳定 ID 和图片内容均不得重复；若当日一期已完成，检查结果后停止，不再生成重复提交。

不要加入任何个人生成图片、个人图像记录、笔记备份、私人账号信息或凭据；不要修改个人收藏和偏好。只暂存本期明确需要的文件，避免 git add . 带入无关内容。

完成后运行 npm ci（需要时）、npm run check、npm run build，预览并检查本期三图、详情和手机布局。通过后提交并推送到 main，我授权你为这项内容维护创建提交并推送。GitHub Actions 和 Vercel 部署分别核验，报告提交链接和实际部署状态。没有写入权限、不能联网、缺少合适图片或部署失败时明确报告，不把计划或尝试称为完成；恢复后先处理已有待提交内容，不集中补发所有遗漏日期。

---

确认手动链路成功后，可在 dot 中继续要求：“如果你支持定时任务，请每天 08:30（Asia/Taipei）执行以上维护任务。创建后告诉我实际的任务标识、时区和下次执行时间；不支持时请直接说明。”
